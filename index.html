Each comparison is one job: the same cells against two runtimes, with a null phase that bounds the noise first. A CLAIM appears only when the delta is outside that band. Start with the summary tables, then open a run for its numbers; every run links to its raw results/<run-id>/ directory.

Cron and queue arms: cold CLI against the HTTP path

One row per arm from the raw ticks.tsv. Arm A is a cold one-shot CLI process (drush core:cron / queue:run, or the equivalent bench command on Drupal 12), arm B is GET /cron/{key} served by a normal web worker. The CLI arm runs before the web workers are warm, so its wall time is the one to read; the HTTP arm returns before the job finishes on FreeUnit (it detaches), which is why its wall time is the trigger latency.
